# Protocolo de 2–3 sesiones por semana

**El estudiante programa y hace commits.** El asistente orienta con conceptos, criterios, revisión y pistas; no entrega la solución entera salvo petición expresa.

Para cada módulo:
1. Entender el problema/representación. Si es nuevo, video o explicación visual, ejemplos y funcionamiento; definir contrato e invariantes.
2. Implementar operaciones gradualmente **sin copiar un tutorial línea por línea**, depurar y verificar casos básicos.
3. Consolidar tests de límites, secuencias de operaciones, complejidad, limpieza y documentar evidencia de cierre.

No hay cuota de un módulo por semana: simples pueden cerrarse en una sesión y complejas ocupar varias. Commits incrementales que representen avance real, por ejemplo `feat: add dynamic array append`, `test: cover dynamic array growth`, `fix: keep tail consistent after deletion`. Una revisión futura convierte todos los TADs completados a librería; NO se hace esa conversión módulo a módulo.
